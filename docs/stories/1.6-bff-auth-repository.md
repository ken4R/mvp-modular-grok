# Story 1.6 — Repository d'auth branché sur le BFF

Status: Ready

## Story

En tant qu'utilisatrice,
je veux que la connexion appelle le BFF,
afin de remplacer le compte démo par une vraie session.

## Acceptance Criteria

1. Une implémentation `internal` de `AuthRepository` appelle `BffClient.post` sur un chemin documenté, par exemple `/v1/auth/login`.
2. Le JSON de requête et de réponse est défini dans l'impl, pas dans l'api.
3. Les erreurs HTTP deviennent `DomainError.Network` ou `Unauthorized`. La validation reste dans `LoginUseCase`.
4. `LoginViewModel` et les écrans ne changent pas.
5. Le faux repository peut rester derrière le flag ou un binding de test.
6. Aucune feature n'appelle un hôte autre que `NetworkConfig.baseUrl`.
